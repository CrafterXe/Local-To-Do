# Local To Do 备份与恢复说明

## 1. 数据存放位置

```
C:\Users\<用户名>\AppData\Roaming\com.localtodo.desktop\
├── local-to-do.db     # 主数据库
├── backups\           # 备份目录
└── logs\              # 日志目录
```

设置页“数据与备份”区域会显示实际路径，并提供打开目录按钮。

## 2. 自动备份

- 默认开启，间隔 24 小时（可在设置中选择更短周期）。
- 应用运行期间每 30 分钟检查一次是否到期，到期则自动备份。
- 每次备份生成两个文件：
  - `local_to_do_backup_YYYYMMDD_HHMMSS.json`：平台无关的完整数据（清单、任务、步骤、笔记、重复规则、提醒计划、设置、历史）。
  - `local_to_do_backup_YYYYMMDD_HHMMSS.db`：SQLite 数据库快照（`VACUUM INTO` 生成，可直接用 SQLite 工具打开）。
- 最多保留最近 20 份自动/手动备份，超出后自动清理最旧文件。

## 3. 手动备份

设置页点击“立即备份”，立即生成一份 JSON + .db 备份，并刷新“上次备份”时间。建议在大版本升级、批量修改或导出前执行一次。

## 4. 导出

- **导出 JSON**：选择保存位置，导出完整结构化数据，适合迁移和程序化处理。
- **导出 CSV**：导出任务清单（包含任务名称、清单、到期日期、时间、重要、完成、备注、重复规则等中文字段），适合在 Excel 中查看。

导出操作不会修改本地数据库。

## 5. 恢复

入口：设置页“从备份恢复”，或在“最近的备份文件”列表中点击某个 JSON 备份的“恢复”。

流程：

1. 选择 `.json` 备份文件（`.db` 快照用于手工排查，不参与一键恢复）。
2. 程序先校验备份格式与版本。
3. 界面会明确提示“恢复将覆盖当前全部数据”，必须确认后才会执行。
4. 恢复在单个事务中完成：清空现有业务表，按依赖顺序写入备份数据，随后重建全部提醒计划。
5. 恢复完成后界面自动刷新，并提示恢复的清单、任务、笔记、重复规则数量。

注意事项：

- 恢复前建议先“立即备份”当前数据，避免误操作后无法回退。
- 恢复会覆盖当前数据，但不会删除备份目录中的历史备份文件。
- 如果备份文件损坏或格式不匹配，程序会拒绝执行并给出错误提示，不会改动现有数据。

## 6. 手工备份 / 迁移

在应用完全退出后，直接复制整个 `%APPDATA%\com.localtodo.desktop` 目录即可实现完整迁移。复制前建议先退出应用，确保 WAL 日志已合并。

## 7. 灾难恢复

若数据库文件损坏：

1. 退出应用。
2. 将损坏的 `local-to-do.db` 重命名为 `local-to-do.db.bak`。
3. 启动应用，会创建空数据库。
4. 在设置页使用最近的 `.json` 备份执行恢复。

## 8. 未来 Android 迁移

JSON 备份为平台无关格式，字段不依赖 Windows 路径或注册表。未来 Android 客户端可直接解析该 JSON 完成数据导入。数据库中的时间统一以 UTC 毫秒存储，日期使用 `YYYY-MM-DD`、时间使用 `HH:MM` 字符串，便于跨平台复用。
