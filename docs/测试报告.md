## 3. 提醒场景测试（A–J）

| 场景 | 状态 | 说明 |
|---|---|---|
| A. 1 分钟后提醒，验证 Windows 通知 | 调度通过 / 横幅未能本机确认 | 调度器按时触发并记录“已发送提醒通知”；新增 AUMID 注册后，Windows 通知平台已接收该通知（注册表 `LastNotificationAddedTime` 更新）。但本机桌面环境对包括 PowerShell 自带通知在内的所有 Toast 均不渲染横幅（对照测试同样不可见），故不将“横幅可见”标记为通过，需在普通桌面会话人工确认 |
| B. 5 分钟后提醒，关闭主窗口仅留托盘 | 关闭/恢复已验证，提醒横幅待人工 | 已实测：点击关闭后进程存活并记录“窗口已隐藏到系统托盘”；再次启动可恢复窗口，调度线程独立于窗口。通知横幅可见性同场景 A |
| C. 创建提醒后重启应用，提醒仍有效 | 通过（逻辑+单元测试） | 启动时 `refresh_all_reminders` 依据任务重建 pending 计划；`cargo test` 覆盖计划创建；应用重启实测见下方说明 |
| D. 每周一、三、五 20:30 的下一次提醒 | 通过 | 领域单元测试覆盖“每周一三五”的 `next_after` 计算 |
| E. 每月 31 日在无 31 日月份的处理 | 通过 | 单元测试验证 2 月 28/29 日、4 月 30 日收缩 |
| F. 睡眠错过提醒后唤醒 | 通过（逻辑） | 调度线程每 20 秒扫描，错过 ≤24 小时补发并标注“（延迟提醒）”，>24 小时标记 missed；真实睡眠需人工验证 |
| G. 删除已设提醒任务后取消通知 | 通过 | `cargo test` 覆盖提醒取消；删除任务会取消 pending 计划 |
| H. 完成重复任务生成下一周期 | 通过 | 集成测试验证生成下一周期并继承规则/步骤 |
| I. 断网后创建、编辑、保存、提醒 | 通过（架构保证） | 应用无任何网络请求代码；全部功能走本地 SQLite 与本地调度。建议现场断网复测 |
| J. 关闭并重开，任务/笔记/清单/设置完整 | 通过（多次实测） | 开发版与发布版多次关闭/重开，任务、清单、笔记、设置、备份列表均完整保留 |

### 仍需人工执行的系统级步骤

1. 安装正式版后，在设置页点击“发送测试”，确认 Windows 通知中心出现“Local To Do”测试通知。
2. 创建 1 分钟后的提醒，等待通知横幅（场景 A）。
3. 创建 5 分钟后的提醒，点击窗口关闭按钮，确认进程仍在托盘、通知按时出现（场景 B）。
4. 创建提醒后，从托盘“退出”，重新启动应用，确认提醒计划恢复（场景 C）。
5. 让电脑睡眠跨过提醒时间，唤醒后确认收到“（延迟提醒）”通知（场景 F）。
6. 断开网络后重复创建、编辑、完成任务与笔记，确认无任何异常（场景 I）。
7. 完全退出并重启 Windows，确认数据完整（场景 J）。

## 4. 测试中发现并修复的问题

| 问题 | 修复 |
|---|---|
| 取消完成/再次保存任务会为已触发的时间点重新创建提醒，导致重复弹窗 | `sync_schedule` 检查同任务同触发时间是否已有 `fired` 记录，若有则不再创建；新增回归测试 |
| 侧栏清单数量与管理按钮（⋯）重叠 | 为清单计数增加右侧留白 |
| 快捷添加只能按 Enter，鼠标用户缺少明确按钮 | 输入内容后显示“添加”按钮 |
| 设置页任务/笔记统计在数据变化后不刷新 | 进入设置页及数据变更后自动刷新统计与备份列表 |
| 直接 `cargo build --release` 生成的程序加载 devUrl（显示 127.0.0.1 拒绝连接） | 发布构建必须启用 `tauri/custom-protocol` 特性；已用 `cargo build --release --features tauri/custom-protocol` 重新构建并重新打包验证 |
| 未安装 Win32 程序缺少通知身份，Toast 可能被系统丢弃 | 应用启动时自动写入 AUMID 注册表项（DisplayName / IconUri） |
| IExpress 安装包提示“创建进程 <None> 时出错” | SED 的 `SourceFiles0` 路径缺少结尾反斜杠，补上后正常打包 |

## 6. 结论

- 编译、类型检查、25 项 Rust 测试、10 项前端测试全部通过。
- 核心任务流程、重要标记、完成状态、详情面板、笔记、设置统计已在真实 UI 中操作验证。
- 提醒调度、去重、错过补发、重复任务生成本身已通过自动化测试。
- 官方 NSIS 安装包与备用安装包的安装、开始菜单启动、静默卸载、数据与安装目录分离均已在真实系统上完成实测。
- 应用启动时会自动登记 AUMID（`HKCU\Software\Classes\AppUserModelId\com.localtodo.desktop`），解决未安装 Win32 程序 Toast 被系统丢弃的问题。
- Windows 原生通知的最终横幅展示、托盘后台、真实重启/睡眠场景需在普通桌面会话上按第 3 节步骤人工确认；本报告不将未执行的系统级场景标记为通过。
